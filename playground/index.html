Mini wallet playground

Every seam of mountMiniWallet as a switch. Flipping one remounts both corners from the live dist/app-shell.js, so rebuild with bun run build:dist and reload. The wallet is a mock by default, which lets you click through every state without a real Hub. Switch it to Real Hub to drive the actual popup.

Wallet

Backend

Mock implements the same Wallet interface the corner consumes, the way Hashmark's betting-key adapter does.

Runtime mode

In miniapp mode the wallet is ambient: the face collapses to a flag and the menu keeps language only.

Presence

Unchecking the first is the language-only corner (a kid app on device pairing, a portal chooser).

Balances

Multi-asset shows NIM plus USDT plus BTC, each with its own decimals (5 / 6 / 8) and its own latency.

Reader behaviour

A throwing reader must keep the last value on screen. An unpriced asset must be left OUT of the total, not counted as zero.

Seams

An unwired seam renders no row, which is the corner's no-dead-buttons rule. Toggle one off and watch it vanish.

Send

Send is NOT an ordinary seam. The button is always there, and with no send option it opens the mini wallet's own recipient + amount view, which calls wallet.pay(). Passing send replaces that with your own flow.

Mock pay outcome

Only applies to the Mock backend. A cancel must stay silent (closing a wallet dialog is a normal outcome, not an error); a failure must say so.

Report a bug

Real posts to bot.nimiq.tech, which drafts the issue with an LLM and files it, labelled playground. It creates an actual issue, so close it afterwards. nimiq-app-shell is in the list on purpose: the service answers unknown_repo for it, which is how you see the reporter's error path.
